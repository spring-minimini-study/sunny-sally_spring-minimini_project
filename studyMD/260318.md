## Spring minimini 세번째 스터디

#### 1. MiniSpringApplication.java
스프링 부트 애플리케이션의 시작점.

* `@SpringBootApplication`: 스프링 부트의 핵심 시작 어노테이션

#### 2. TestController.java
서버가 정상적으로 실행되는지 확인하기 위한 테스트용 컨트롤러. `/test` 요청이 들어오면 간단한 문자열을 반환함.

* `@RestController`: 이 클래스가 HTTP 요청을 처리하는 컨트롤러라는 뜻. 반환값을 뷰가 아니라 응답 데이터로 바로 내려줌
* `@GetMapping("/test")`: GET 요청 `/test`를 이 메서드와 연결. 브라우저에서 `/test`로 들어오면 해당 메서드가 실행됨


#### 3. UserController.java
사용자 관련 요청(조회, 생성)을 처리하는 컨트롤러. 클라이언트가 보낸 요청을 받아 서비스 계층에 전달하고 결과를 응답함.

* `@RestController`: 사용자 관련 API 요청을 처리하는 컨트롤러임을 표시
* `@GetMapping("/users/{id}")`: GET 요청 `/users/{id}`를 처리. 사용자 1명 조회에 사용
* `@PathVariable("id")`: URL 경로의 `{id}` 값을 메서드 파라미터로 받아옴 (예: `/users/1` -> `id = 1`)
* `@PostMapping("/users")`: POST 요청 `/users`를 처리. 사용자 생성에 사용
* `@RequestBody`: 요청 본문(JSON)을 자바 객체로 변환해서 받음 (예: `{ "name": "jisu" }` -> `UserCreateRequest`)


#### 4. UserService.java
사용자 관련 비즈니스 로직 처리. Controller와 Repository 사이에서 실제 동작을 담당.

* `@Service`: 이 클래스가 서비스 계층이라는 뜻. 비즈니스 로직을 담당하는 클래스임을 스프링에 알림


#### 5. UserCreateRequest.java
사용자 생성 요청을 받을 때 사용하는 DTO. 클라이언트가 보낸 JSON 데이터를 담는 객체.

* 사용된 어노테이션 없음


#### 6. UserResponse.java
사용자 정보를 응답으로 반환할 때 사용하는 DTO. 클라이언트에게 어떤 형식으로 데이터를 줄지 정의함.

* 사용된 어노테이션 없음


#### 7. User.java
사용자 데이터를 DB 테이블과 연결하는 엔티티. 실제로 데이터베이스에 저장되는 객체.

* `@Entity`: 이 클래스가 JPA 엔티티라는 뜻. DB 테이블과 매핑되는 대상
* `@Table(name = "users")`: 테이블 이름을 `users`로 지정. 기본 이름 `user` 대신 사용해서 예약어 충돌 방지
* `@Id`: 기본키(PK) 필드 지정. 각 사용자 데이터를 구분하는 고유값
* `@GeneratedValue(strategy = GenerationType.IDENTITY)`: 기본키 값을 DB가 자동 생성하도록 설정. 저장 시 `id`가 자동 증가함


#### 8. UserRepository.java
사용자 데이터를 DB에 저장/조회하는 Repository. `JpaRepository<User, Long>` 상속을 통해 스프링이 자동으로 빈 등록 및 구현을 제공하여 CRUD 기능을 수행함.

* 직접 선언한 어노테이션 없음


### 전체 구조 요약

| 계층 (Layer) | 역할 |
| :--- | :--- |
| **Controller** | 요청 받기, URL 연결, 요청 데이터를 Service에 전달, 응답 반환 |
| **Service** | 비즈니스 로직 처리, Controller와 Repository 연결 |
| **Repository** | DB 저장 및 조회 담당 |
| **Entity** | DB 테이블과 매핑되는 객체 |
| **DTO** | 요청 및 응답 전용 데이터 객체 |
