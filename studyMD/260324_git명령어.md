## Git 기본 명령어 정리

자주 쓰는 기본 명령어만 빠르게 볼 수 있게 정리.

### 1. 상태 확인

* `git status`
  현재 변경된 파일 상태 확인

* `git log --oneline`
  커밋 히스토리를 한 줄씩 간단히 확인

* `git diff`
  아직 커밋하지 않은 변경 내용 확인

### 2. 파일 추가와 커밋

* `git add .`
  전체 변경 파일 스테이징

* `git add 파일명`
  특정 파일만 스테이징

* `git commit -m "메시지"`
  스테이징된 변경 사항 커밋

### 3. 브랜치 작업

* `git branch`
  현재 브랜치 목록 확인

* `git branch 브랜치명`
  새 브랜치 생성

* `git checkout 브랜치명`
  해당 브랜치로 이동

* `git checkout -b 브랜치명`
  브랜치 생성 후 바로 이동

### 4. 원격 저장소 작업

* `git pull origin 브랜치명`
  원격 저장소 변경 내용 가져와 반영

* `git push origin 브랜치명`
  현재 브랜치 내용을 원격 저장소에 업로드

* `git clone 저장소주소`
  원격 저장소를 로컬로 복제

### 5. 자주 같이 쓰는 흐름

```bash
git status
git add .
git commit -m "작업 내용 정리"
git push origin 브랜치명
```

기본 작업 흐름:
변경 확인 -> 스테이징 -> 커밋 -> 푸시

### 6. merge

* `git merge 브랜치명`
  현재 브랜치에 다른 브랜치 내용을 합치기

* `git merge feature/login`
  `feature/login` 브랜치 내용을 현재 브랜치에 병합

정리:
브랜치를 하나로 합칠 때 사용

### 7. rebase

* `git rebase 브랜치명`
  현재 브랜치 커밋을 다른 브랜치 기준 위로 다시 정렬

* `git rebase main`
  현재 브랜치를 `main` 최신 기준으로 다시 맞춤

정리:
커밋 흐름을 깔끔하게 정리할 때 사용

주의:
이미 공유한 브랜치에서는 조심해서 사용

### 8. reset

* `git reset --soft HEAD~1`
  최근 커밋 1개를 취소하고 스테이징 상태는 유지

* `git reset --mixed HEAD~1`
  최근 커밋 1개를 취소하고 스테이징도 해제

* `git reset --hard HEAD~1`
  최근 커밋 1개와 작업 내용까지 모두 되돌림

정리:
커밋 취소나 작업 되돌리기에 사용

주의:
`--hard`는 변경 내용을 복구하기 어려우니 신중하게 사용

### 9. stash

* `git stash`
  현재 작업 내용을 잠시 보관

* `git stash list`
  저장한 stash 목록 확인

* `git stash pop`
  가장 최근 stash를 다시 적용하고 목록에서 제거

* `git stash apply`
  가장 최근 stash를 다시 적용하지만 목록은 유지

정리:
작업 중 급하게 브랜치를 바꾸거나 잠시 치워둘 때 사용

### 10. 상황별 자주 쓰는 예시

#### 다른 브랜치 작업 내용 합치기

```bash
git checkout main
git merge feature/login
```

#### main 최신 내용 기준으로 내 브랜치 정리하기

```bash
git checkout feature/login
git rebase main
```

#### 방금 커밋만 취소하고 수정 이어가기

```bash
git reset --soft HEAD~1
```

#### 작업 중인 내용 잠깐 보관하기

```bash
git stash
git stash pop
```

### 11. fork

`fork`는 다른 사람의 원격 저장소를 내 GitHub 계정으로 복사해 오는 것.

정리:
원본 저장소에 직접 push 권한이 없을 때 내 저장소로 복사해서 작업하는 방식

#### fork와 clone 차이

* `fork`
  GitHub에서 원격 저장소를 내 계정으로 복사

* `clone`
  원격 저장소를 내 컴퓨터로 복제

즉:
`fork`는 GitHub 안에서 복사
`clone`은 내 로컬 컴퓨터로 복사

#### fork 후 기본 작업 흐름

1. GitHub에서 원본 저장소를 fork
2. 내 fork 저장소를 `git clone`
3. 브랜치 생성 후 작업
4. `add` -> `commit` -> `push`
5. GitHub에서 Pull Request 생성

#### 자주 보는 흐름 예시

```bash
git clone 내-fork-저장소주소
git checkout -b feature/login
git add .
git commit -m "로그인 기능 추가"
git push origin feature/login
```

#### upstream 개념

* `origin`
  보통 내가 fork한 저장소

* `upstream`
  보통 원본 저장소

예시:

```bash
git remote add upstream 원본-저장소주소
git fetch upstream
git checkout main
git merge upstream/main
```

정리:
원본 저장소 최신 변경 내용을 내 fork 저장소에 반영할 때 자주 사용
