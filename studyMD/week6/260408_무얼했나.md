
### 1) Member 엔티티 작성

구성한 필드:
- `id`
- `name`
- `email`
- `password`

적용한 내용:
- `@Entity` : JPA가 관리하는 엔티티라는 뜻.
- `@Id` : 기본 키 설정
- `@GeneratedValue(strategy = GenerationType.IDENTITY)`
  - : 엔티티의 기본 키 값을 어떻게 자동 생성할지 지정하는 어노테이션
  - `GenerationType.IDENTITY`: DB가 직접 AUTO_INCREMENT 같은 방식으로 id를 증가시킴
  - `GenerationType.SEQUENCE`: DB의 시퀀스(sequence) 객체를 사용해서 id 생성.
    - Oracle, PostgreSQL 같은 DB에서 자주 쓰임
    - 저장 전에 번호 발급 가능 -> 대량 insert나 성능 최적화 측면에서 유리한 경우가 있음
  - `GenerationType.AUTO`: JPA가 DB 환경에 맞춰 자동으로 적절한 방법을 사용

- `createMember(MemberCreateRequest request)`: 회원 생성
- `getMember(Long memberId)` : 회원 단건 조회

`@Service`:
- 스프링이 Bean으로 등록하여 관리하게 해줌
- 객체를 직접 new MemberServie() 하지 않아도 되고 다른 곳에서 주입받아서 쓸 수 있다.

---

### 6) MemberController 구현

구현한 API:
- `POST /members`
- `GET /members/{id}`

적용한 내용:
- `@RestController`: 이 클래스가 REST API 컨트롤러라는 뜻. 반환값을 JSON 형태로 내려줌
- `@RequestMapping("/members")`: 이 컨트롤러의 공통 URL 경로를 `/members`로 지정한다.
- `@PostMapping`: HTTP POST 요청을 처리하는 메서드에 붙인다. -> 요청 body의 JSON을 MemberCreateRequest로 받음
- `@GetMapping("/{id}")`: HTTP GET 요청을 처리하는 메서드에 붙이고, URL 경로의 {id}값을 받아서 조회
- `@RequestBody`: 요청 본문(JSON 등)을 자바 객체로 변환해서 받는다.
- `@PathVariable`: URL 경로에 들어 있는 값을 메서드 파라미터로 받는다.

### 7) Swagger 적용 준비

정리한 의존성:
- `implementation("org.springdoc:springdoc-openapi-starter-webmvc-ui:3.0.2")`

적용 후 확인한 내용:
- Swagger UI 접속 주소
- OpenAPI 문서 주소
- Swagger에서 API를 테스트하는 방법
- `@Tag`, `@Operation` 같은 문서용 어노테이션 사용 가능 여부

어노테이션 설명:
- `@Tag`: Swagger 문서에서 API를 그룹으로 묶을 때 사용하는 어노테이션이다.
- `@Operation`: 각 API의 설명, 요약, 동작 내용을 문서에 표시할 때 사용하는 어노테이션이다.

정리한 접속 주소:
- `http://localhost:8080/swagger-ui/index.html`
- `http://localhost:8080/v3/api-docs`

### 8) interface + impl 구조와의 비교

비교한 내용:
- 왜 강의에서는 interface + impl 구조를 사용하는가?
- 왜 지금 내 코드에서는 그렇게 하지 않았는가?

이해한 내용:
- interface + impl 구조는 결합도를 낮춰 구현체를 바꿔끼우기 쉽게 하기 위해 사용한다.
- 예를 들어 결제 기능에서 카카오페이 결제 로직과 토스페이 결제 로직을 교체하는 상황에 유리하다.
- 반면 지금 단계의 코드는 구조를 익히는 것이 우선이라서, 우선은 단순한 단일 구현체 구조로 진행해도 충분하다는 점을 이해했다.

## 4. 오늘 이해한 핵심 개념들

### 엔티티
- DB 테이블과 연결되는 객체
- JPA가 관리하는 저장 대상

### DTO
- 데이터를 주고받기 위한 객체
- 요청용, 응답용으로 나뉨

### Repository
- DB 접근 담당
- 기본 CRUD 처리

### Service
- 실제 비즈니스 로직 담당
- Controller와 Repository를 연결

### Controller
- HTTP 요청을 받는 입구
- 요청을 Service에 전달하고 응답 반환

### Swagger
- API 문서 확인 도구
- 브라우저에서 직접 API 테스트 가능
