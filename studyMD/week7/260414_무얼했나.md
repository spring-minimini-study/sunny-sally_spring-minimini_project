## 1. `JpaRepository<Member, Long>`의 상속 구조
*`JpaRepository<Member, Long>`: MemberRepository 클래스가 상속받는 인터페이스.

- `Repository`
- `CrudRepository`
- `PagingAndSortingRepository`
- `JpaRepository`

### `Repository<T, ID>`
- 타입 정보를 잡아주는 최상위 인터페이스.
```
// T = 엔터티 타입
// ID = 기본 키 타입
public interface Repository<T, ID> {

}
```

### `CrudRepository<T, ID>`
- 기본 CRUD 기능이 여기서 생김
- save, findById, existsById, findAll, count, deleteById, delete, deleteAll 등

### `ListCrudRepository<T, ID>`
- `CrudRepository`의 List 버전

### `PagingAndSortingRepository<T, ID>`
- 정렬과 페이징 기능을 주는 인터페이스.
- findAll(Sort sort)와 findAll(Pageable pageable)
```
memberRepository.findAll(Sort.by("name"));
memberRepository.findAll(PageRequest.of(0, 10));
// 이런 식으로 사용
```
### `ListPagingAndSortingRepository<T, ID>`
- `PagingAndSortingRepository`의 List 버전

### `QueryByExampleExecutor<T>`
- 예제 객체 기반 조회 기능
- findOne, findAll, findAll(..., Sort), findAll(..., Pageable), count, exists, findBy 등

### 최종: `JpaRepository<T, ID>`
- 위 기능들 + JPA 전용 메서드
- flush(), saveAndFlush(), saveAllAndFlush(), deleteAllInBatch(), deleteAllByIdInBatch(), getReferenceById() 등
```
public interface JpaRepository<T, ID>
        extends ListCrudRepository<T, ID>, // CRUD
                ListPagingAndSortingRepository<T, ID>, // 페이징과 정렬
                QueryByExampleExecutor<T> { // 조회

    void flush();

    <S extends T> S saveAndFlush(S entity);

    <S extends T> List<S> saveAllAndFlush(Iterable<S> entities);

    void deleteAllInBatch();

    void deleteAllInBatch(Iterable<T> entities);

    void deleteAllByIdInBatch(Iterable<ID> ids);

    T getReferenceById(ID id);
}
```

## 2. JPA에 대한 탐구

- JPA(Jakarta Persistence API): 객체와 관계형 데이터베이스를 매핑해서 다루기 위한 표준.
- ORM(Object Relational Mapping): 객체와 관계형 데이터베이스를 연결해주는 방식
    - ORM이 필요한 이유
        : 관계형 DB는 테이블, 컬럼, 행 중심이고, 자바는 객체 필드, 참조 중심이기 때문!
    - ORM을 안쓰면
        - SQL 직접 작성, 파라미터 바인딩, 결과 꺼내기, 객체 변환을 전부 해야함

        - ORM없이 JDBC로 직접 하면 이런 식으로 해야함
            ```
            Connection conn = dataSource.getConnection();
            PreparedStatement ps = conn.prepareStatement(
                "insert into member(name, email, password) values (?, ?, ?)"
            );
            ps.setString(1, member.getName());
            ps.setString(2, member.getEmail());
            ps.setString(3, member.getPassword());
            ps.executeUpdate();

            // 조회
            PreparedStatement ps = conn.prepareStatement(
                "select id, name, email, password from member where id = ?"
            );
            ps.setLong(1, id);
            ResultSet rs = ps.executeQuery();
            ```
- Hibernate
    : 자바용 ORM 프레임워크
    : JPA의 구현체 중 하나
- Spring Data JPA
    : JPA를 더 편하게 쓰게 해주는 스프링 계층
    - Spring Data JPA 없이 JPA를 쓸 수 있나?
        : 가능
        - JPA만 쓰면
            - EntityManager 주입
            - 저장 메서드 작성
            - 조회 메서드 작성
            - 반복되는 Repository 코드 작성
            을 해야함. 이렇게!
            ```
            @Repository
            public class MemberJpaRepository {

                @PersistenceContext
                private EntityManager em;

                public void save(Member member) {
                    em.persist(member);
                }

                public Member findById(Long id) {
                    return em.find(Member.class, id);
                }
            }
            ```
        - Spring Data JPA를 쓰면
            : 인터페이스만 선언해도 기본 CRUD와 페이징, 정렬, 이름 기반 query method까지 쉽게 쓸 수 있다.
            이렇게만 구현하면 됨! 대박
            ```
            public interface MemberRepository extends JpaRepository<Member, Long> {
                        boolean existsByEmail(String email);
            }
            ```
    - Spring Data JPA의 역할
        - Repository 추상화 제공
        - 보일러플레이트 감소
            (*보일러플레이트: 최소한의 수정으로 여러 곳에서 재사용되는 반복적인 코드나 텍스트 블록)
        - Query Method 지원
            : 메서드 이름만으로 쿼리를 만들 수 있게 해줌. 대표기능

- "초등학생도 이해할 수 있게 설명해줘"
    - JPA = 운전 법규
    - Hibernate = 실제 자동차
    - Spring Data JPA = 네비게이션/운전 보조 기능
    
- 실제 내 프로젝트에서
    - JPA
        - @Entity
        -  @Id
        - @GeneratedValue
    - Hibernate
        : memberRepository.save(member) 했을 때 실제 SQL insert를 만들고 H2 DB에 저장하는 역할
    - Spring Data JPA
        - JpaRepository<Member, Long>
        - save(), findById(), findAll()와 같은 Repository 편의 기능 제공
### JPA를 쓰는 이유
- 객체 중심 개발이 가능
- SQL/JDBC 반복 코드를 줄일 수 있음
- 엔티티 중심으로 저장/조회/수정 흐름을 다룰 수 있음
- DB 테이블과 자바 객체 연결을 구조적으로 다룰 수 있음
### JPA 핵심 개념
1. 엔티티
    : 내가 new Member(..)로 객체를 만들면 JPA구현체(Hibernate)가 적절한 SQL insert로 바꿔줌
2. 식별자와 @Id
    ```
    @Id // 이 필드가 PK다.
    @GeneratedValue(strategy = GenerationType.IDENTITY) // PK값을 자동 생성하겠다.
    private Long id;
    ```
3. 영속성(Persistence)
    : JPA는 단순히 SQL 한 번 보내는 도구라기보다, 엔티티 객체를 DB와 연결된 상태로 관리하는 개념임
### existsByEmail() 같은 건 왜 되냐
: Spring Data JPA가 메서드 이름을 해석해서 쿼리를 만드는 기능 덕분.

## 3. Docker에 대해
: 애플리케이션을 실행하는 데 필요한 환경까지 함께 묶어서 어디서든 똑같게 실행되게 해주는 도구
: "내 컴퓨터에서는 되는데요?" 문제를 줄여주는 기술
### 왜 필요하냐
: 사람마다 환경이 달라서 발생하는 문제를 없애기 위해.
=> 애플리케이션과 실행 환경을 함께 포장한다.
### 가상머신이랑 뭐가 다른가
- 가상머신
    - 운영체제까지 통째로 띄움
    - 부팅 느린 편
- 도커
    - 필요한 실행 환경만 격리해서 띄움
    - 훨씬 가볍고 빠름
### 핵심 개념
- 이미지
    : 실행에 필요한 설계도(요리 레시피)
- 컨테이너
    : 실제로 실행 중인 프로그램
- Dockerfile
    : 이미지를 만드는 방법을 적는 파일
### 내 플젝에 적용
- 나중에
    - 팀원이 내 플젝을 똑같이 실행하고 싶을 때
    - 내 컴퓨터 말고 서버에서 돌리고 싶을 대
    - Java 버전 차이 문제를 없애고 싶을 때
    - MySQL까지 같이 묶어서 실행하고 싶을 때
### 흐름
1. 프로젝트를 jar로 빌드
2. Dockerfile 작성
3. 이미지 생성
4. 컨테이너 실행
=> 내 Spring 앱이 도커 컨테이너 안에서 실행됨
