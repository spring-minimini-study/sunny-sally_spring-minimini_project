## Git 기본 명령어 정리

자주 사용하는 Git 명령어를 상황별로 정리했다.  
명령어를 외우는 것보다 "언제 어떤 목적에 쓰는지" 함께 이해하면 훨씬 헷갈리지 않는다.

### 1. 상태 확인

- `git status`
  현재 변경된 파일 상태를 확인한다.

- `git log --oneline`
  커밋 히스토리를 한 줄씩 간단하게 확인한다.

- `git diff`
  아직 커밋하지 않은 변경 내용을 확인한다.

### 2. 파일 추가와 커밋

- `git add .`
  현재 폴더 기준으로 변경된 파일을 한 번에 스테이징한다.

- `git add 파일명`
  특정 파일만 선택해서 스테이징한다.

- `git commit -m "메시지"`
  스테이징된 변경 사항을 커밋한다.

### 3. 브랜치 작업

- `git branch`
  현재 브랜치 목록을 확인한다.

- `git branch 브랜치명`
  새 브랜치를 생성한다.

- `git checkout 브랜치명`
  해당 브랜치로 이동한다.

- `git checkout -b 브랜치명`
  브랜치를 생성한 뒤 바로 이동한다.

- `git switch 브랜치명`
  브랜치를 이동한다. 최근에는 `checkout` 대신 이 명령어도 많이 사용한다.

- `git switch -c 브랜치명`
  브랜치를 새로 만들고 바로 이동한다.

### 4. 원격 저장소 작업

- `git pull origin 브랜치명`
  원격 저장소의 변경 내용을 가져와 현재 브랜치에 반영한다.

- `git push origin 브랜치명`
  현재 브랜치의 내용을 원격 저장소에 업로드한다.

- `git clone 저장소주소`
  원격 저장소를 로컬 컴퓨터에 복제한다.

### 5. 자주 쓰는 기본 흐름

```bash
git status
git add .
git commit -m "작업 내용 정리"
git push origin 브랜치명
```

기본 작업 흐름:
변경 확인 -> 스테이징 -> 커밋 -> 푸시

### 6. git remote

`git remote`는 현재 로컬 저장소와 연결된 원격 저장소 정보를 확인하거나 수정할 때 사용하는 명령어다.

- `git remote`
  등록된 원격 저장소 이름만 간단히 확인한다.

- `git remote -v`
  원격 저장소 이름과 URL을 함께 확인한다.

- `git remote add origin 저장소주소`
  `origin`이라는 이름으로 원격 저장소를 추가한다.

- `git remote add upstream 저장소주소`
  `upstream`이라는 이름으로 원본 저장소를 추가한다.

- `git remote remove origin`
  등록된 원격 저장소를 삭제한다.

- `git remote rename origin upstream`
  원격 저장소 이름을 변경한다.

정리:
원격 저장소를 새로 연결하거나, 연결 상태를 확인하거나, 이름을 바꿀 때 사용한다.

#### 자주 보는 예시

```bash
git remote -v
git remote add origin https://github.com/username/repository.git
git remote add upstream https://github.com/original-owner/repository.git
```

#### `origin`과 `upstream`

- `origin`
  보통 내가 직접 clone했거나 fork한 뒤 연결된 기본 원격 저장소다.

- `upstream`
  보통 내가 참고하거나 동기화해야 하는 원본 저장소다.

예를 들어 fork 방식으로 작업할 때는 보통 내 저장소를 `origin`, 원본 저장소를 `upstream`으로 등록한다.

### 7. `git fetch`와 `git pull` 차이

`fetch`와 `pull`은 둘 다 원격 저장소의 변경 내용을 가져올 때 사용하지만, 동작 방식이 다르다.

| 명령어 | 의미 | 현재 브랜치에 바로 반영되는가 | 주로 쓰는 상황 |
| :--- | :--- | :--- | :--- |
| `git fetch` | 원격 변경 사항만 가져옴 | 아니오 | 먼저 확인하고 나중에 직접 반영하고 싶을 때 |
| `git pull` | 가져온 뒤 바로 병합하거나 rebase | 예 | 바로 최신 상태를 반영하고 싶을 때 |

#### `git fetch`

- `git fetch origin`
  원격 저장소 `origin`의 변경 내용을 가져온다.

- `git fetch upstream`
  원본 저장소 `upstream`의 변경 내용을 가져온다.

정리:
원격 변경 내용을 일단 가져오기만 하고, 내 작업 브랜치에는 바로 합치지 않는다.

#### `git pull`

- `git pull origin main`
  `origin`의 `main` 브랜치 내용을 가져와 현재 브랜치에 바로 반영한다.

- `git pull upstream main`
  `upstream`의 `main` 브랜치 내용을 가져와 현재 브랜치에 바로 반영한다.

정리:
가져오기와 반영을 한 번에 처리한다.

#### 언제 `fetch`를 먼저 쓰면 좋은가

- 원격에 어떤 변경이 있는지 먼저 확인하고 싶을 때
- 자동 병합 전에 충돌 가능성을 미리 보고 싶을 때
- 바로 작업 브랜치에 반영하지 않고 비교부터 하고 싶을 때

예시:

```bash
git fetch origin
git log --oneline main..origin/main
```

위 흐름은 원격의 최신 커밋을 먼저 가져오고, 내 브랜치와 어떤 차이가 있는지 확인할 때 자주 사용한다.

### 8. merge

- `git merge 브랜치명`
  현재 브랜치에 다른 브랜치의 작업 내용을 합친다.

- `git merge feature/login`
  `feature/login` 브랜치의 내용을 현재 브랜치에 병합한다.

정리:
브랜치를 하나로 합칠 때 사용한다.

### 9. rebase

- `git rebase 브랜치명`
  현재 브랜치의 커밋을 다른 브랜치를 기준으로 다시 정렬한다.

- `git rebase main`
  현재 브랜치를 `main`의 최신 기준 위로 다시 올린다.


참고: https://brunch.co.kr/@anonymdevoo/7

정리:
커밋 흐름을 더 깔끔하게 정리하고 싶을 때 사용한다.

주의:
이미 다른 사람과 공유한 브랜치에서는 신중하게 사용해야 한다.

### 10. reset / revert / restore

Git에서 "되돌리기" 관련 명령어는 비슷해 보여도 대상과 결과가 다르다.

| 명령어 | 대상 | 히스토리 변경 여부 | 주로 쓰는 상황 |
| :--- | :--- | :--- | :--- |
| `reset` | 커밋, 스테이징 상태 | 바뀔 수 있음 | 최근 커밋 취소, 스테이징 되돌리기 |
| `revert` | 특정 커밋 | 기존 히스토리 유지 | 이미 push한 커밋을 안전하게 취소 |
| `restore` | 작업 파일, 스테이징 상태 | 히스토리는 바뀌지 않음 | 파일 수정 내용 되돌리기 |

#### `git reset`

- `git reset --soft HEAD~1`
  최근 커밋 1개를 취소하고 스테이징 상태는 유지한다.

- `git reset --mixed HEAD~1`
  최근 커밋 1개를 취소하고 스테이징도 해제한다.

- `git reset --hard HEAD~1`
  최근 커밋 1개와 작업 내용까지 모두 되돌린다.

정리:
커밋 위치를 뒤로 돌리거나 스테이징 상태를 바꾸고 싶을 때 사용한다.

주의:
`--hard`는 변경 내용을 복구하기 어려울 수 있으므로 특히 조심해야 한다.

#### `git revert`

- `git revert HEAD`
  가장 최근 커밋을 취소하는 새 커밋을 만든다.

- `git revert 커밋해시`
  특정 커밋의 내용을 되돌리는 새 커밋을 만든다.

정리:
기존 커밋을 지우지 않고, 취소 내용을 새로운 커밋으로 남긴다.

주의:
이미 원격 저장소에 push한 커밋을 되돌릴 때 더 안전하다.

#### `git restore`

- `git restore 파일명`
  작업 중인 파일의 수정 내용을 마지막 커밋 상태로 되돌린다.

- `git restore --staged 파일명`
  스테이징한 파일을 다시 unstaged 상태로 되돌린다.

정리:
파일 단위로 작업 내용을 되돌리거나 스테이징을 취소할 때 사용한다.

#### 언제 무엇을 쓰는가

- 최근 커밋 자체를 취소하고 싶다.
  `git reset`

- 이미 push한 커밋을 안전하게 되돌리고 싶다.
  `git revert`

- 파일 수정 내용만 취소하고 싶다.
  `git restore`

#### 간단 비교 예시

```bash
git reset --soft HEAD~1
git revert HEAD
git restore app.js
```

차이:

- `reset`
  커밋 위치를 뒤로 이동한다.

- `revert`
  취소 내용을 새 커밋으로 남긴다.

- `restore`
  파일 상태만 되돌린다.

### 11. stash

- `git stash`
  현재 작업 내용을 잠시 보관한다.

- `git stash list`
  저장한 stash 목록을 확인한다.

- `git stash pop`
  가장 최근 stash를 다시 적용하고 목록에서 제거한다.

- `git stash apply`
  가장 최근 stash를 다시 적용하지만 목록은 유지한다.

정리:
작업 중 급하게 브랜치를 바꾸거나 잠시 변경 내용을 치워둬야 할 때 사용한다.

### 12. 상황별 자주 쓰는 예시

#### 다른 브랜치 작업 내용 합치기

```bash
git checkout main
git merge feature/login
```

#### `main` 최신 내용 기준으로 내 브랜치 정리하기

```bash
git checkout feature/login
git rebase main
```

#### 방금 커밋만 취소하고 수정 이어가기

```bash
git reset --soft HEAD~1
```

#### 작업 중인 내용 잠깐 보관하기

```bash
git stash
git stash pop
```

#### 원격 저장소 확인하고 연결하기

```bash
git remote -v
git remote add origin 저장소주소
git push -u origin main
```

#### 원격 변경 내용만 먼저 확인하기

```bash
git fetch origin
git log --oneline HEAD..origin/main
```

### 13. fork

`fork`는 다른 사람의 원격 저장소를 내 GitHub 계정으로 복사해 오는 기능이다.

정리:
원본 저장소에 직접 push 권한이 없을 때, 내 저장소로 복사해서 작업하는 방식이다.

#### fork와 clone 차이

- `fork`
  GitHub 같은 원격 서비스에서 저장소를 내 계정으로 복사한다.

- `clone`
  원격 저장소를 내 컴퓨터로 복제한다.

즉:
`fork`는 원격 서비스 안에서 복사하는 것이고,  
`clone`은 내 로컬 컴퓨터로 가져오는 것이다.

#### fork 후 기본 작업 흐름

1. GitHub에서 원본 저장소를 fork 한다.
2. 내 fork 저장소를 `git clone` 한다.
3. 브랜치를 생성한 뒤 작업한다.
4. `add` -> `commit` -> `push` 순서로 반영한다.
5. GitHub에서 Pull Request를 생성한다.

#### 자주 보는 흐름 예시

```bash
git clone 내-fork-저장소주소
git checkout -b feature/login
git add .
git commit -m "로그인 기능 추가"
git push origin feature/login
```

#### upstream 개념

- `origin`
  보통 내가 fork한 저장소를 가리킨다.

- `upstream`
  보통 원본 저장소를 가리킨다.

예시:

```bash
git remote add upstream 원본-저장소주소
git fetch upstream
git checkout main
git merge upstream/main
```

정리:
원본 저장소의 최신 변경 내용을 내 fork 저장소에 반영할 때 자주 사용한다.

### 14. 핵심 요약

- 기본 흐름은 `status -> add -> commit -> push`다.
- 원격 저장소 연결과 확인에는 `git remote`를 사용한다.
- 원격 변경 내용을 먼저 확인할 때는 `fetch`, 바로 반영할 때는 `pull`을 사용한다.
- 브랜치를 합칠 때는 `merge`, 흐름을 정리할 때는 `rebase`를 사용한다.
- 되돌리기 계열 명령어는 `reset`, `revert`, `restore`의 차이를 꼭 구분해서 사용해야 한다.
